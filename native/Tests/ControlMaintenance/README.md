# GenDragoon maintenance implementation and disposable proofs

This isolated area does not participate in native builds or product runtime. It contains a concrete root controller and fixed inspector/network adapters prepared locally for review. **No live activation has been performed. The default controller and existing release runner remain NO_GO; the new implementation still requires its exact Ubuntu CI result, independent audit, a reviewed private execution bundle and a fresh native app-closed proof with periodic observation and per-phase challenges.** The dedicated workflow requires Ubuntu and exactly Node **20.20.2**, matching the inspected server. It automatically runs for pull requests changing this fixture directory or its own workflow, and checks out the exact pull-request head SHA. Manual dispatch remains available once the workflow is registered on the default branch; do not dispatch a duplicate when an automatic run already exists. GitHub documents the default-branch requirement for [workflow_dispatch](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_dispatch).

`control33-drain-local-proof.cjs` loads the historical Control source using `git show f01e25b63ea87b2d0d0892bfd910683e2d94ff84:native/RedXCloud/control-server.cjs` and requires SHA256 `176ebea80c72bb6ae73017d58829fdde50489164a1a26319fb49699424e391d2`. That matches the read-only live source inspection. It compiles those unmodified bytes plus the historical ControlState and RedXState dependency bytes, each pinned to the independently verified live hash. The actual stores are injected disposable fakes; the fixture does not claim a live-provider drain. It uses an issuer backed by actual native loopback fetch and its real eight-second abort signal, and a fake Stripe object permitting only the 31 catalog reads. No product source copy, live key, live account, live Stripe call or remote connection is required.

A Node inspector Session connects to **the fixture's own process**, without opening an inspector TCP listener. Runtime.getProperties returns lexical references in memory. Only the actual handler, identify, secureFetch and serial function sources and named accountLocks reference are retained. Complete scopes are never serialized, logged or returned. Provenance checks compare the actual function sources with the exact historical source. The fixture schedules installation through an ordinary in-target setImmediate callback. It installs a nonwritable, nonconfigurable own set method on the actual accountLocks Map, preserving Map.prototype and its original get/delete/tails. Future serial calls throw at that dynamic set before the first await and before fn; already admitted and queued tails complete unchanged. It then replaces the actual request listener synchronously before closing that server and keeps the disposable process alive with its own interval. The old admission fence cannot be restored.

The tests demonstrate that a pipelined request on a previously accepted socket is rejected before identity lookup, disconnected work inside serial and same-owner queued tails prevent readiness until their actual completion, and pre-identity disconnected work is denied at the original serial admission boundary after the fence. A stronger adversary exposed that a native fetch response body can complete after its original eight-second abort signal on Node20.20.2. The late completion is then denied by the map fence before fn. Readiness requires server-close completion, the intact immutable own-map admission fence, an empty captured account-lock map, and no unfinished rejected responses. The 8250ms timer remains adversarial telemetry only; no timeout or socket-quiet sample acts as completion evidence. Unadmitted identity reads may remain in the old process, but cannot later start business work. This is a business-work admission/drain argument, not a claim that every native read promise has settled.

The Python tests execute actual Node metadata traversal against disposable three-table records, verify all deletion representations independently block, hash real disposable PNG and sidecar files without changing them, reject unsafe links and nonempty writer locks, and exercise actual loopback HTTP redirect/proxy fixtures. `--activate` on the tested server artifact always fails before root, files, requests or service operations. Its only permitted subprocess operation is `systemctl show`.

The `adapter/` implementation uses the same source-bound mechanism. `server-admission-gates-36.cjs` compares actual handler/serial/identity/fetch function strings and installs the immutable map fence and refusal listener from an ordinary target `setImmediate` callback. Receiver scalar counters are retrieved through **fresh function `[[Scopes]]` reads every time**. V8 can retain an old scope object's scalar snapshot; caching that object produced false zero counts in the adversarial fixture. The actual collection references remain stable and are checked separately. Neither gate restores old admission or removes a writer lock. Their owned intervals keep closed old processes alive until ordinary service stop.

`external-inspector-boundary.test.cjs` exercises the actual external client and admission library against only a forked disposable child. It proves same-owner queued and disconnected old work prevents readiness; the original native eight-second identity abort fires while old work is still held; the actual native body is read before its abort, while an explicitly injected `text()` completion promise retains that copied value until **after the original abort signal and actual readiness**, then is refused at the actual map admission boundary; and inspector shutdown acknowledges before the client disconnects and the owned port disappears. This external test reports native-body-read timing separately from injected completion scheduling; it does not claim its underlying transport ignored abort. The unchanged historical self-inspector proof independently retains the observed native-body-after-abort adversary. The initial Ubuntu implementation run `40353530418` failed the former external assumption that native transport must remain pending through abort, then timed out during missing failure cleanup; its later controller/kernel steps were skipped. The new fixture has a bounded timeout, awaited owned-client/raw-socket cleanup and natural child exit, and synchronizes IPC completion telemetry before asserting it. Discovery also rejects real redirects, noncanonical hosts, userinfo and queries, and ignores hostile proxy variables. The client validates the pinned source before connecting and disconnects its owned WebSocket on every error/EOF path while retaining target fences and the guard. The root controller verifies the actual target-owned listener and reciprocal TCP socket pair belonging to its client before/after gate operations, and refuses another session. A mandatory Linux disposable test connects a real second WebSocket client and proves that refusal. The client uses literal IPv4 loopback, bounded replies and a fixed Runtime-method allowlist. It cannot accept caller-supplied Runtime expressions, heap capture, browser sessions or UI operations.

`receiver35-drain-local-proof.cjs` loads unmodified historical Receiver35 and dependencies in memory with pinned hashes and disposable injected stores. It captures the handler scopes before five held requests, then uses the actual admission library. Disconnected pre-identity and store work, two real owned fake-codec Node children, a queued decoder waiter and a retained pipeline socket exercise the original request/decoder/container counters. Readiness stays false until all actual callbacks and children complete. All PNG/sidecar byte buffers and the complete fake ledger match before and after the original `cloud.close()` removes only its own empty writer lock. This fixture does **not** execute the original OS SIGTERM main entrypoint, and does not claim live provider transaction outcomes.

`server-network-boundary-36.py` defaults to render-only and disables kernel mutations unless the reviewed root controller explicitly opts in. It creates one fresh nonce-owned nft table, verifies exact contents and handles, and never adopts or changes another table. Root-only loopback 9229 protection precedes any inspector enable. Service SYN fences are added only after a fresh verified Control drain; existing connections remain available to the in-process wrappers. Cleanup needs fresh debugger-absence, process and preserved-state proofs. The Python test includes offline adversaries and an actual isolated Linux network namespace. CI makes that kernel proof mandatory; a missing prerequisite or capability is a failure, not a skip. It tests root/non-root reachability, Control's prior Receiver dependency, new SYN refusal, established-connection survival and preservation of an unrelated table/port. The workflow installs prerequisites only on its disposable CI runner.

`server-activation-controller-36.py` defaults to capability inspection. Its optional execution mode is restricted to Linux root, exact pinned sources/manifests, private reviewed bundle bytes **verified before backend imports**, host/boot/PID/start/executable/UID/cgroup/command/environment provenance, and an acknowledged successful implementation CI commit. Commands use absolute trusted executable paths with an explicit sanitized environment. Inspector enable is bound to a Linux pidfd and revalidates the exact old PID/start identity before signaling; it never signals a numeric PID after an unchecked wait. Actual `/proc/PID/cgroup` membership and every descendant `cgroup.procs` are checked, and candidate PID/start/full-environment identity is pinned at startup and retained across phases. The Mac coordinator holds the existing maintenance lease and answers a newly collected challenge before every remote phase after checking screen unlock, strict upload queue state, lifecycle idle and the native app closed. While remote stdout is idle, it polls the same signed-input and lifecycle proof every one second plus inspection duration; stdout selection waits at most0.5s, and partial lines are buffered without a blocking readline. Any failed/unknown proof closes only the coordinator stdin pipe. The remote controller holds before its next phase when it observes EOF. Already issued operations are allowed to settle; this observer sends no cancellation or process signal. Observation is periodic and bounded, not an atomic interlock that prevents an uncooperative native relaunch. Before importing installed helpers it verifies the existing frozen build-provenance SHA, all 86 repository inputs, all 37 exact packaged mappings, the complete signed bundle and its CodeDirectory identity. The verified existing lifecycle helpers check strict queue schema and active_job_id, dirty VFS metadata, active launch sessions, open bundle/cache files, mounts and helper work. Imports and Python subprocesses explicitly disable bytecode generation. An open app, stale/nonfinite proof, protected state or disconnected coordinator stops progress. There is no force-quit or UI fallback.

The controller leaves Receiver available while previously admitted Control work drains, closes inspectors sequentially with ACK/disconnect, then proves Receiver requests, decoders, containers and cgroup children empty. It takes complete stable three-table and PNG/sidecar snapshots, then makes full independent byte copies of **every** payload-manifest file beneath a new private directory using exclusive creation. Capacity must cover all bytes plus8KiB per file and a margin of the larger of1GiB or10percent. Each source is checked for link/file identity and read stability, every copy is fsynced, and independent reopen/hash/size checks must match the drained manifest; directories are also fsynced. A new complete metadata/payload scan must still match before the backup becomes eligible. `configure()` independently refuses an absent/corrupted full backup before its first config action. The live backend requires the exact same explicit Mac gate instance as the phase controller. After long backup verification and provenance reads it obtains another fresh acknowledged proof before the first config copy/write, then another immediately before daemon reload. Stop/link-switch boundaries also recheck after provenance reads, and network cleanup rechecks after candidate manifest hashing before creating its fresh typed cleanup proof. After each blocking acknowledgement, bounded post-gate continuity checks revalidate the already pinned PID/start/full-environment identity, actual cgroup and listener state, executable/source stat identity, or the complete stopped state and old links/config. Each systemd show is bounded to two seconds. The original received proof timestamp is checked again against the strict ten-second limit immediately before mutation; elapsed time is not reset and there is no RPC retry loop. The controller-owned network backend checks that same retained proof again at mutation dispatch after nft readback/syntax validation, separately from the existing typed network proof TTL. Configuration atomic writes and mutating service commands also check freshness at dispatch. A withdrawn, expired or changed-state proof causes a hold before the following action. These are ordinary byte copies, not hardlinks, and no restore/delete operation is implemented. The controller retains private original configuration, writes only the two GenDragoon no-force/infinite-stop drop-ins and Control-only token overlay, requests ordinary service stops, compares stopped preservation, and atomically switches only the reviewed environment/current links. Control starts before Receiver. Private health, credential/listener/process checks and full after-start preservation must pass before public admission reopens. The existing token and pinned read-only helper are streamed in a private pipe for the service-identity probe; they never appear in argv, child environment, logs or receipts. Both the remote controller invocation and the probe use Python `-I -S -B`; the controller also refuses optimized Python before any backend/assertion-helper import. The probe uses a fixed sanitized environment, preventing inherited PYTHONPATH or user-site startup from influencing the trusted stdlib-only helper. Shared `/opt/redx/etc/redxd.env` remains read-only with its existing ownership/mode.

`test-activation-state-machine-36.py` runs only disposable models and files, never constructs the live backend. It injects failure at every backend operation and withdraws the Mac gate before every phase. It proves no later action or automatic cleanup occurs, dependency order is preserved, data drift prevents admission release, originals remain retained, and no force, manual lock removal or database restore is used. The 47 controller tests include direct disposable process/cgroup trees and mocked kernel calls for descendant membership, exact candidate PID/start/environment continuity and pidfd targeting. They also exercise real private-file and atomic-replacement boundaries, verify the service probe pipe, reject nonfinite timestamps, test lifecycle queue/cache/session/open-file failures, and confirm unreviewed execution or an invalid signed Mac bundle fails before mutation-backend import, helper import, lease or SSH. Additional tests make actual disposable full-byte backups that survive source changes, reject low capacity/source drift/copy corruption before configuration, and exercise the periodic idle observer and fresh phase replies. The actual Linux socket test is the one platform-specific local skip; Ubuntu must run it. These tests support the controller's order; they do not replace exact-host root review or the independent live-provider outcome condition.

The failure policy is a **safe hold**. Only the fixed root-private `phase.json` leaf may persist completion/HOLD evidence after a long phase expires its Mac proof. Its writer validates the exact current nonce-owned root0700 backup directory and fixed filename, retains root0600 mode, and uses exclusive temporary creation, fsync and atomic replacement. It accepts no destination path or bypass flag. Normal `atomic()` configuration/evidence-copy writes remain proof-gated. The private root phase journal and original configuration are retained along with all still-needed admission fences, process holds and network guards. No automatic rollback, old admission restoration, payload removal, manual writer-lock removal, database restore or Stripe write is implemented. A failed service-identity probe after public admission reopens retains the remaining debugger guard and requires root diagnosis. Failure receipts explicitly report `candidateMayBeRunning`, `publicAdmissionMayBeOpen` and possible guard cleanup; `activated` is unknown once startup may have occurred, and success requires `activationComplete=true`; it does not silently claim that public admissions are still blocked. Recovery or rollback needs a separately reviewed candidate drain and preservation proof. The current local app-running condition continues to prevent any live step. The existing deployment authorization is sufficient for reviewed work; root review is engineering validation, and human help is needed only if normal native Quit cannot be performed through the available UI.
